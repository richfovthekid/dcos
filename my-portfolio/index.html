Engineering Debug & Architecture Case Studies / 工程排错与架构优化案例

1. AI Agent Function Calling Route Fallback Bug / AI 智能体函数调用路由降级缺陷修复

Background / 背景: AI assistant lacked the "create order" tool but failed to intercept gracefully, forcing structured order data into a regular "task" template and causing cross-module data confusion. AI 助手缺失“创建订单”工具时未能优雅拦截，导致结构化订单数据被强行塞入常规“任务”模板，引发跨模块数据混淆。

Root Cause / 根因: Function Calling scope lacked registration for the tool. Without fallback logic, the model appended raw parameters into the description field and downgraded execution. Function Calling 作用域未注册该工具，且缺少兜底拦截逻辑，致使模型将原始参数拼入描述字段并降级执行。

Fix & Validation / 修复与验证: Registered the order tool chain in the backend and refined the System Prompt to enforce strict boundary interception and rejection logic. 后端补全订单工具链注册，并优化系统提示词（System Prompt），强制执行严格的边界拦截与拒绝逻辑。

2. State Machine Missing Enum Validation & Flow Defect / 状态机缺少枚举校验与流转缺陷修复

Background / 背景: Project task state change interfaces lacked defensive logic; closed tasks could be illegally reversed to pending, and non-standard strings were accepted by the database. 项目任务状态变更接口缺乏防御性逻辑，已关闭任务可被非法逆向回滚至待处理状态，且数据库接收了非标字符串。

Root Cause / 根因: Controller/DTO layers lacked Enum whitelist verification, and the underlying Service lacked a state machine transition map, leaving constraints unprotected. Controller/DTO 层缺少枚举白名单校验，底层 Service 缺少状态机流转图谱，约束形同虚设。

Fix & Validation / 修复与验证: Implemented hardcoded Enum whitelist protection at the DTO layer (returning 400 Bad Request for invalid inputs) and introduced a state machine validator to block terminal state reversals. 在 DTO 层落地硬编码枚举白名单保护（非法输入直接返回 400 Bad Request），引入状态机校验器拦截终态逆向。

3. ORM Mapping Deadlock Caused by Unvalidated Inputs / 未校验输入导致的 ORM 映射死锁修复

Background / 背景: Order creation allowed non-numeric text (e.g., "abc") to be stored. Subsequent edits caused the system to frequently crash and deadlock due to type conversion failures. 订单创建允许存入非数字文本（如 "abc"），后续编辑时系统因类型转换失败频繁崩溃死锁。

Root Cause / 根因: Table fields were defined as VARCHAR. During updates, the ORM pre-loaded entities and threw a NumberFormatException when mapping "abc" to an Integer field during the read phase, blocking writes. 表字段定义为 VARCHAR，更新时 ORM 预加载实体并在读阶段将 "abc" 映射至 Integer 字段抛出 NumberFormatException 导致写阻塞。

Fix & Validation / 修复与验证: Corrected the database schema to INT, added @Min(1) validation in the backend DTO, and enforced frontend type and regex limits to establish a three-tier closed-loop protection. 修正数据库表结构为 INT，后端 DTO 增加 @Min(1) 校验，前端同步限定类型与正则，构建三层防御闭环。
